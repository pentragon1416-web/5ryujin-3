**龍神**は、2人のプレイヤーが**ボードの上に駒を置いていく**ゲームです。  
オンラインでも遊べるようになっており、世界中の人と対戦できます。

---

## 🎮 ゲームの遊び方（簡単版）

```
1. 駒を選ぶ
   ↓
2. ボード上で駒を動かす
   ↓
3. 置きたい場所を決める
   ↓
4. 駒を置く
   ↓
5. 手番が交代する
   ↓
6. 相手が同じように駒を置く
```

これを繰り返して、最後に駒を置けなくなった方が負けです。

│  ┌────────────────────────────────────┐ │

│  │  ・駒選択ボタン                     │ │
│  │  ・手番表示                        │ │
│  │  ・時間カウントダウン               │ │
│  └────────────────────────────────────┘ │
└─────────────────────────────────────────┘

### 裏側の仕組み（データ流れ）
```
プレイヤー操作
    ↓
[入力検出]
    ↓
[駒選択ロジック] → Board, PieceButton
    ↓
[駒の移動] → PieceCursor
    ↓
[配置可能判定] → MdMap
    ↓
[データ記録] → RecordManager / NetworkRecordManager
    ↓
[手番交代] → Board, Timer
```

## 📚 システムの3つの段階

このゲームは、3つの大きな段階を経て完成しました。

### 段階1️⃣：基本システム（初期段階）
**何ができるようになったか**
- 1つのパソコンで2人が遊べるようになった
- 駒をボードに置ける
- 手番を交代できる

**使っているクラス**
```
Board              ← ゲーム全体を管理（手番、ターン、ルール）
PieceCursor        ← マウスに追従する駒
Stock              ← 駒の残り数を管理
PieceButton        ← UI上の駒選択ボタン
```

### 段階2️⃣：記録＆再生システム（中期段階）
**何ができるようになったか**
- ゲーム内容を記録できるようになった
- 過去のゲームを再生できるようになった
- 駒の形や動きをデータとして定義できるようになった

**使っているクラス**
```
PieceData          ← 駒の形を定義（どんな形の駒か）
PieceInfo          ← 駒の変換情報（回転、反転）
PieceDatabase      ← 全ての駒のデータを保管する図書館
MoveData           ← 1回の移動データ（どの駒を、どこに置いたか）
MoveDataLoader     ← MoveDataを読み込んで実行する
RecordManager      ← ゲームの棋譜（記録）を保存・読み込み
ReplayManager      ← 過去のゲームを再生する
```

**例：MoveData の中身**
```
{
  "駒の種類": "T",
  "置いた位置": (x=3, y=5),
  "回転角度": 90度,
  "反転": なし
}
```

### 段階3️⃣：オンラインシステム（現在）
**何ができるようになったか**
- インターネット経由で別のパソコンの人と遊べるようになった
- 世界中の人とリアルタイムで対戦できるようになった
- 2人の画面が常に同期される（同じ状態が見える）

**使っているクラス**
```
Photon Fusion      ← ネットワーク通信の仲介役（GoogleやAmazonみたいな大企業が提供）
GameLauncher       ← ゲーム開始時の準備をする
NetworkRunner      ← ネットワーク接続を管理
NetworkRecordManager    ← ネット用の記録管理
NetworkPieceCursor      ← ネット用の駒カーソル
NetworkCursorTracker    ← 相手の操作を追跡
NetworkCursorViewer     ← 相手の操作を画面に表示
NetworkController       ← ネットワークの制御全般
GameUIForNetwork        ← ネット用のUI表示
MessageController       ← メッセージ表示（ゲーム状態の通知など）
```

## 🎯 重要なクラス解説

各クラスを、身近な例でわかりやすく説明します。

### 🏠 Board（ボード管理者）
**役割**：ゲーム全体のルール番人
```
例：銀行の支店長のような存在

- 現在どちらのプレイヤーの番か？ → 管理
- ゲーム開始時に何をするか？ → 指示
- ゲーム終了の判定 → 判定
- 駒が全部置けなくなった？ → 確認
```

### 🎯 PieceCursor（駒のマウスポインタ）
**役割**：選ばれた駒がマウスについてくる
```
例：磁石に吸い寄せられる鉄粉のような動き

- ボタンが押されたら駒を出現させる
- マウスが動くたびに駒も動く
- クリックしたら「この場所に置く」という指令を出す
- 置けなかったら駒を戻す
```

### 📦 Stock（駒の在庫）
**役割**：各プレイヤーの駒の残り数を管理
```
例：店の倉庫のような存在

- 駒A は何個残ってる？ → 数える
- 駒Aがなくなったら？ → 選択できなくする
- 駒を置いたら残り数を1減らす → 記録
```

### 📍 MdMap（盤面ルール）
**役割**：「この場所に駒が置けるかどうか」を判定
```
例：建設会社が「ここに建物を建てられるか」を判定するようなもの

- 通路として使われているタイル？ → ダメ
- 既に駒が置いてある？ → ダメ
- 前の駒に触れている？ → OK（ルール）
- 浮いている？ → ダメ
```

### 💾 RecordManager（棋譜の記者）
**役割**：ゲーム内容を記録して保存する
```
例：将棋の新聞記者が大事な対局を記録するようなもの

プロセス：
1. 駒が置かれるたびに記録する
   「13:05 プレイヤーA が駒Tを(3,5)に置いた」
2. 記録をファイルに保存する
   ファイル名：KIF.001, KIF.002, ...
3. あとから読み込んで再生できるようにする
```

### 🔄 ReplayManager（再生機）
**役割**：保存したゲーム内容を再生する
```
例：DVDプレイヤーのような存在

- 保存ファイルを読み込む
- 記録されたMoveData を1つずつ実行
- 画面上で駒がもう一度置かれていく
- 最後には同じゲーム状態になっている
```

### 🎨 PieceData（駒のカタログ）
**役割**：各種類の駒がどんな形か定義する
```
例：おもちゃ屋のカタログ

駒T の形：
  ・タイル構成：
    ┌─┬─┬─┐
    │ │ │ │
    └─┴─┴─┘
       │ │
       └─┘
  ・磁石位置：角に4個

駒I の形：
  ・タイル構成：
    ┌─┬─┬─┬─┐
    │ │ │ │ │
    └─┴─┴─┴─┘
  ・磁石位置：所定の位置
```

### 🗂️ PieceDatabase（駒の図書館）
**役割**：全ての駒の情報を一箇所に管理
```
例：図書館の司書

質問：「駒F の情報が欲しい」
司書：「ここだよ」→ PieceData を返す

スピード重視で、すぐに探せる工夫がされている
```

### 📊 MoveData（移動記録）
**役割**：1回の移動を全て記録
```
MoveData = {
  "駒の種類": "T",
  "位置X": 3,
  "位置Y": 5,
  "回転": 90度,
  "反転": false,
  "ターン": 5,
  "プレイヤー": 1P,
  "タッチダウン": true
}

このデータがあれば、その瞬間を完全に再現できる
```

### 🌍 ネットワーククラス（オンライン機能）

#### **NetworkRecordManager（ネット記者）**
```
通常の RecordManager とほぼ同じだが、
インターネット越しで2人のデータを同期する
```

#### **NetworkPieceCursor（ネット駒カーソル）**
```
通常の PieceCursor とほぼ同じだが、
相手のパソコンにも移動情報を送信する
```

#### **NetworkCursorTracker & NetworkCursorViewer（相手の操作追跡）**
```
例：テレビ電話で相手の動きが見えるように、
    相手がマウスをどこに動かしているか、
    ずっと監視して画面に表示する
```

#### **MessageController（メッセージ表示）**
```
例：駅の電光掲示板

重要なお知らせを画面に表示：
- 「接続中です、お待ちください」
- 「相手の番です」
- 「ゲーム終了！あなたの勝ちです！」
```

## 📞 ゲーム中のデータの流れ（詳細版）

### シナリオ：プレイヤーが駒を置く場合

```
1. プレイヤー：「駒ボタン T を押す」
   ↓
2. PieceButton：「T が押された。現在の手番は？」
   → Board に確認「今は1Pの番？」
   ↓
3. Board：「はい、1Pの番です」
   ↓
4. Stock：「駒T は残ってる？」
   → PieceDatabase から駒T の形を取得
   ↓
5. PieceCursor：「駒T を生成して表示する」
   → マウスについてくるようにする
   ↓
6. プレイヤー：「マウスを動かす」
   ↓
7. PieceCursor：「マウスについてく。毎フレーム PieceInfo で回転・反転を計算」
   ↓
8. プレイヤー：「ここに置こう」→「クリック」
   ↓
9. MdMap：「この場所に置けるかチェック」
   - 他の駒にぶつかってないか？
   - 前の駒に付いてるか？（ルール）
   ↓
10. MdMap：「OK、置けます」
    ↓
11. PieceCursor：「駒を固定する」
    ↓
12. MoveData を生成：
    {
      "駒": T,
      "位置": (x, y),
      "回転": 90,
      "反転": false
    }
    ↓
13. RecordManager（またはNetworkRecordManager）：「この MoveData を記録する」
    ↓
14. Stock：「駒T の残数を 1 減らす」
    ↓
15. Board：「手番を 1P から 2P に変える」
    ↓
16. Timer：「時間をリセット」
    ↓
17. MessageController：「相手の番です」と表示
```

### ネットワーク版での追加処理

```
上記の処理に加えて：

12. NetworkRecordManager：「この MoveData を RPC で相手に送信」
    ↓
    （相手のパソコン）
    ↓
13. NetworkRecordManager：「RPC受信。同じ MoveData を実行」
    ↓
14. MoveDataLoader：「相手のボードにも同じ駒を置く」
```

## 🗺️ 次のフェーズ：ネット対戦の棋譜記録システム

オンライン化の開発完了後、**ネット対戦で行われたゲームの棋譜をローカルに記録する機能**を実装する予定です。

### 実装の概要

**既存のシステムを活用した実装**
```
現在のシステム：
- RecordManager ✅ JSON ファイル保存（ローカルゲーム用）
- MoveDataLoader ✅ 記録を復元・実行
- NetworkRecordManager ✅ ネット対戦のデータ同期

次のフェーズで追加：
- NetworkRecordManager から MoveData 配列を抽出
- RecordManager と同じ方式で JSON ファイルに保存
- MoveDataLoader で復元して再生
```

### 実装の流れ

```
オンラインゲーム終了
  ↓
NetworkRecordManager から全 MoveData を取得
  ↓
JSON形式に変換
  ↓
RecordManager で ONLINE_GAME_001.json として保存
  ↓
あとから MoveDataLoader で読み込み＆再生可能に
```

### なぜ簡単に実装できるのか

すでに以下が完成しているため：

| 実装済み | 役割 | 利用方法 |
|--------|------|---------|
| **MoveData** | 移動データ構造 | そのまま JSON 化して保存 |
| **MoveDataLoader** | 記録の実行 | 保存した JSON から復元して使用 |
| **NetworkRecordManager** | ネット同期 | 配列データを抽出するだけ |
| **RecordManager** | JSON 保存 | 実装済みの方法をそのまま応用 |

### 実装方法

```csharp
// 1. ゲーム終了時に、NetworkRecordManager から MoveData 配列を取得
MoveData[] gameMoves = networkRecordManager.GetAllMoves();

// 2. GameRecord へ変換
GameRecord record = new GameRecord();
record.moves = new List<MoveData>(gameMoves);

// 3. RecordManager で JSON 保存（既存実装をそのまま流用）
recordManager.SaveGameAsJson("ONLINE_GAME_" + gameId, record);

// 4. 後から復元して再生
MoveData[] loadedMoves = recordManager.LoadGameFromJson("ONLINE_GAME_001");
foreach(var move in loadedMoves) {
    moveDataLoader.LoadMoveData(move);
}
```

## 🚀 その他の拡張可能性

このシステムの設計により、以下の拡張も簡単に実装できます：

```
✅ 駒の種類を増やす
   → PieceData アセットを追加するだけ

✅ ルールを変える
   → MdMap の判定ロジックを変更

✅ AIを追加
   → AI が PieceButton を自動で押すようにする

✅ ゲームモードを追加
   → 3人対戦、タイムアタック など

✅ ランキングシステム
   → ゲーム結果を記録・集計
   （※MoveData記録実装後は簡単）

✅ 統計分析ツール
   → MoveData を分析して戦術を可視化
```

## 💡 まとめ

このゲームは、以下の3つの技術的段階を経て完成しました：

| 段階 | 技術的課題 | 解決方法 |
|-----|----------|---------|
| **1** | 1つのパソコンで複数プレイヤーをサポート | MonoBehaviour での状態管理 |
| **2** | ゲーム進行の記録と再生 | データ構造の設計と永続化 |
| **3** | ネットワーク通信 | Photon Fusion の活用 |

これらの段階を経ることで、**単純なゲームロジック**から**複雑なオンラインシステム**へと進化しました。

各クラスは単一の責任を持ち、他のクラスと協力することで、全体が動いています。
